    • Core run

      Main screening pipeline

      Every full run passes through receptor, pocket, ligand, filter, engine, backend, and submission decisions.

      • Step 1

        Choose receptor source

        Local PDB/PDBQT, RCSB PDB ID, AlphaFold ID, or uploaded structure.

        • Prep

          Prepare receptor

          Chain selection, heteroatom handling, protonation logic, QC, and PDBQT conversion.

          pdbfixerMeekoPDB2PQRPROPKA
      • Step 2

        Choose binding site path

        Co-crystal ligand, residue-defined box, P2Rank prediction, or blind docking box.

        • Pocket tools

          Compute and validate box

          Top-3 pocket suggestions, geometry build, and box sanity checks.

          P2RankJavabox validator
      • Step 3

        Choose ligand source

        SMILES, SDF, Mol2, Mol, PDB, ZINC, ChEMBL, sketcher, or uploaded library.

        • Ligand prep

          Normalize and prepare ligands

          Convert formats, enumerate variants, embed 3D, minimize, QC, and convert to dockable files.

          RDKitGypsum-DLOpenBabelMeeko
      • Step 4

        Choose filters and depth

        ADMET pre-filter on or off, search depth, and preparation settings.

        • Filter

          Apply chemistry filters

          Rule-based ligand triage before compute-heavy docking.

          Ro5PAINSBrenkVeberEgan
      • Step 5

        Choose docking engine

        UniDock on Kaggle, local Vina, DiffDock-L, Vinardo, consensus, or rescoring paths.

        • Engines

          Execution engine profile

          The engine determines score type, box requirement, GPU need, and downstream result semantics.

          UniDockAutoDock VinaNVIDIA NIMGNINA
      • Step 6

        Choose compute backend

        Single Kaggle account, multi-account/team distribution, local CPU, or headless orchestration route.

        • Orchestration

          Shard, render, submit, poll, resume

          Ligands are split, notebooks rendered, datasets uploaded, kernels pushed, and failed shards resumed.

          Jinja2Kaggle APISQLiteThreadPoolExecutor
    • Post-run

      Results and analysis

      Once docking returns, ezscreen turns raw shard outputs into review artifacts that still require scientific interpretation.

      • Merge

        Merge shard outputs

        Combine CSVs and poses, deduplicate, rerank globally, attach LE/BEI, score type, and variant collapse state.

      • Validation

        Check pose validity

        Run physical plausibility and geometry checks on downloaded poses.

        PoseBusters
      • Interactions

        Analyze protein-ligand contacts

        Optional post-run interaction extraction and fingerprinting.

        PLIPProLIFOpenBabel
      • Clustering

        Cluster and benchmark hits

        Scaffold clustering plus implemented benchmarking helpers; some evaluation paths remain planned rather than fully validated.

        RDKit ButinaAUC-ROCEF1%
      • Outputs

        Generate final deliverables

        Results viewer, HTML report, Methods paragraph, Excel export, SDF export, annotations, and shareable review artifacts.

        Mol*RDKit SVGopenpyxl
    • Support paths

      Non-run commands and maintenance

      Support features that sit beside the main run pipeline.

      • Auth

        Credential setup

        Kaggle account validation, optional NIM validation, credentials file management.

      • Status

        Live run monitoring

        See queued, running, failed, resumed, and completed runs.

      • Resume

        Resume failed shards

        Recover failed jobs from checkpoint and local run context.

      • View

        Inspect results

        Open viewer and reports independently of the run command.

      • Clean

        Delete remote artifacts

        Remove Kaggle dataset and kernel outputs to free quota and storage.
