# Privacy Policy

Last updated: 2026-07-10

This document describes how ezscreen handles account, team, and run data.

## Scope

ezscreen is a virtual-screening application that can run local workflows and team-managed Kaggle workflows. This policy covers the ezscreen application, its local client state, and the ezscreen team control-plane server.

## Data ezscreen stores

### On the local device
- Kaggle credential file path configured by the user
- NVIDIA NIM API key, if the user saves one
- ezscreen account session state for this device
- team server URL and local team membership context
- run folders, logs, checkpoints, and output files generated by the user

### On the ezscreen team server
- GitHub-based account identity used for sign-in, including GitHub login, GitHub account id, and display name
- ezscreen session records, including creation time, expiry time, and revocation time
- team membership and team role data
- worker metadata such as connected GitHub repository and workflow file
- job metadata, upload-ticket records, callback logs, and result ZIP paths

## Data ezscreen does not store on the team server
- Kaggle API keys
- raw `kaggle.json` contents
- GitHub personal access tokens entered locally for worker setup
- GitHub device-OAuth access tokens used only for sign-in

Kaggle credentials remain on the user's device or in the member-owned GitHub Actions secrets for that worker repository.

## How sign-in works
- ezscreen uses GitHub device OAuth to identify a user
- the team server stores hashed ezscreen session tokens, not plaintext session tokens
- signing out removes the local session from that device and revokes the ezscreen session on the server
- signing out does not remove team membership, pause a worker, or delete worker configuration

## How team runners work
- team jobs are assigned only to members with a connected worker repository
- worker repositories poll the team server for queued jobs on a schedule, so the team server does not need GitHub dispatch credentials or GitHub personal access tokens
- a team member can pause a worker, disconnect a worker, or leave a team without deleting the ezscreen account
- worker repositories may store Kaggle credentials in GitHub Actions secrets under the control of the repository owner
- ezscreen-managed workers are provisioned into dedicated private GitHub repositories so research code and unpublished work do not need to live in the worker repo

## How data is used
We use stored data only to:
- authenticate users
- manage team membership and worker routing
- expose queued jobs to member-owned workers that poll for work
- track run progress and retrieve results
- support local resume, status, and result viewing

## Shared devices
If ezscreen is used on a shared workstation, users should sign out after use. Sign-out removes the ezscreen session from that device but does not remove the user from any team.

## Retention
- local files remain until the user deletes them
- team server records remain until deleted by the operator or by future account/team deletion tooling
- revoked sessions may remain in the database as audit records

## User controls
Users can currently:
- sign in
- sign out
- pause a worker
- disconnect a worker
- leave a team

Future versions may add explicit account-deletion and data-deletion flows.

## Third-party services
ezscreen may interact with third-party services chosen by the user, including:
- GitHub
- Kaggle
- NVIDIA NIM

Use of those services is also governed by their own terms and privacy policies.

## Security
We try to minimize sensitive server-side storage. However, no system can guarantee absolute security. Users should keep local machines, GitHub repositories, and Kaggle accounts secured.
